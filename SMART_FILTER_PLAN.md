# План развития: Умный Фильтр Сигналов (Smart Filter)

Этот документ содержит концепцию и технические детали для улучшения качества сигналов. К реализации этого плана стоит приступать только после подтверждения полной автономности и стабильности базового бота.

## 1. Цели внедрения
*   **Снижение просадки (Drawdown):** Исключение входов в сделки в моменты обвала рынка.
*   **Повышение Winrate:** Отсеивание "мусорных" сигналов на неликвидных монетах или на пике роста.
*   **Автоматическая защита:** Бот сам решает, безопасен ли вход, исходя из текущих индикаторов.

## 2. Основные модули фильтрации

### A. BTC Guard (Контекст рынка)
Биткоин — локомотив рынка. Если он летит вниз, стопы по альтам сработают в 90% случаев.
*   **Логика:** Бот проверяет изменение цены BTC за последние 15-60 минут.
*   **Порог:** Если BTC упал > 1.5% за час, вход в любые LONG сигналы блокируется.
*   **Статус:** Рекомендуется как обязательный.

### B. RSI / Bollinger (Защита от "FOMO")
Сигналы часто приходят, когда цена уже перегрета.
*   **Логика:** Проверка индикатора RSI (период 14) на 5m и 15m таймфреймах.
*   **Порог:** Если RSI > 75, вход запрещен (перекупленность).
*   **Bollinger:** Если цена выше верхней границы полос Боллинджера — ждать отката.

### C. Volume Filter (Ликвидность)
Защита от манипуляций на монетах с низким объемом.
*   **Логика:** Проверка 24h объема торгов через API биржи.
*   **Порог:** Минимальный объем — $1,000,000. Если меньше — сигнал игнорируется.

## 3. Архитектура в SignalOnlyStrategy

Фильтр будет вставлен в метод `check_signal_for_entry` (или аналогичный) перед исполнением ордера.

### Пример будущей логики (Псевдокод):

```python
def is_signal_safe(self, pair: str) -> bool:
    # 1. Проверка Биткоина
    if self.get_btc_change_pct() < -1.5:
        logger.warning("SmartFilter: Биткоин падает, вход запрещен.")
        return False
        
    # 2. Проверка перегретости монеты
    rsi = self.get_current_rsi(pair)
    if rsi > 75:
        logger.warning(f"SmartFilter: {pair} перекуплен (RSI={rsi}), пропускаем.")
        return False
        
    # 3. Проверка объема
    volume = self.get_24h_volume(pair)
    if volume < 1000000:
        logger.warning(f"SmartFilter: Низкая ликвидность на {pair}. Пропуск.")
        return False
        
    return True
```

## 4. Мониторинг и Аналитика (Shadow Logging в БД)

Вместо того чтобы просто писать причины отмены сигнала в текстовый лог, необходимо создать отдельную SQLite базу (например, `signal_stats.sqlite`) для хранения истории "раздумий" бота.

### Зачем это нужно?
Логи на миллион строк невозможно анализировать. База данных позволит тебе сделать SQL-запрос и мгновенно увидеть эффективность фильтра: сколько раз он спас депозит, а сколько раз лишил прибыли.

### Что записываем в БД (Поля таблицы):
*   **Timestamp:** Точное время прихода сигнала.
*   **Pair:** Монета.
*   **Signal_Price:** Цена в момент сигнала.
*   **Hypothetical_TP/SL:** Тейк и стоп, которые были в сигнале.
*   **Decision:** Решение бота (ENTER / SKIP).
*   **Reason:** Почему пропустили (например, `BTC_DUMP`, `RSI_OVERBOUGHT`).
*   **Indicators_Snapshot:** Значения всех индикаторов в момент сигнала (RSI, BTC_Change, Volume, Bollinger_Pos).
*   **Market_Context:** Цена BTC, волатильность рынка (ATR).
*   **Result (заполняется позже):** Дошла ли цена до гипотетического Тейка или Стопа (для анализа пропущенных профитов).

## 5. Этапы реализации (в будущем)
1.  **Информационный режим:** Бот записывает ВСЕ сигналы в БД, но в сделку входит всегда. Это нужно для накопления "эталонной" статистики.
2.  **Теневой фильтр:** Бот фильтрует сделки в реальности, но продолжает писать статистику по всем сигналам (включая отброшенные) для анализа.
3.  **Аналитический срез:** Через 2-4 недели ты выгружаешь таблицу в Excel и видишь реальную эффективность каждого индикатора.

## 6. Визуализация и Дашборд (Real-time UI)

Вместо ручной выгрузки данных, необходимо реализовать встроенную веб-страницу (дашборд), которая будет отображать данные из `signal_stats.sqlite` в реальном времени.

### Основные функции дашборда:
*   **Live-таблица сигналов:** Список всех входящих сигналов с цветовой маркировкой (Зеленый — вошли, Серый — отфильтровали).
*   **Счетчик эффективности:** Автоматический расчет метрики "Спасенный депозит" (сколько стоп-лоссов не сработало благодаря фильтру).
*   **Индикатор "Жара":** Визуальное отображение текущих фильтров (например, красный индикатор BTC, если он падает).
*   **Ретро-анализ:** Возможность кликнуть на отфильтрованный сигнал и увидеть график монеты с отметкой, где бы мы вошли и где бы нас выбило.

## 7. Риски
*   **Нагрузка на CPU:** Дашборд должен запрашивать данные по запросу (on-demand), а не держать постоянное тяжелое соединение.
*   **Безопасность:** Доступ к странице статистики должен быть защищен тем же паролем, что и основной FreqUI.
